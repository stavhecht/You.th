# You.th

A masonry feed of short, evidence-checked articles about wellness products and
trends. Each one states what something claims, whether the research actually
supports it, and a plain-language verdict backed by citations to real papers.

Drafts are generated by a retrieval-augmented pipeline over PubMed, Europe PMC,
Semantic Scholar and OpenAlex. **Every draft is reviewed and approved by a human
before it can be published.**

> **The product is You.th; the repository, the Python package and the database
> are still named `evidwell`.** The rename was a design change, not a migration
> — renaming a package, a DSN and a table prefix buys nothing a reader ever
> sees and breaks every local environment that exists. Treat `evidwell` in a
> path or a config key as the internal name for the same thing.

> **Status: implemented and running against a real database.**
>
> 490 tests pass with zero skips, both migrations are applied, and every API
> endpoint has been exercised end to end against Postgres — reviewer auth,
> reader accounts, the review queue, run submission, 401s and 404s. `ruff` is
> clean; the frontend typechecks and builds.
>
> The pipeline has run end to end against **live PubMed and OpenAlex** — 92 real
> papers cached, two articles produced, embedded through **Voyage**. What
> remains unexercised is **Claude**. See **Verification status** below.

## Layout

```
backend/
  app/
    domain/        contracts.py is the spec — every stage's input/output
    llm/           Ollama + Claude clients, factory, and the two prompt templates
      prompts/     extraction.py, synthesis.py
      embeddings/  swappable provider (Ollama default, Voyage/OpenAI hosted)
    retrieval/     scholarly providers, query building, cache, pgvector re-rank
    evidence/      study-type grading, verdict caps, citation validation
    pipeline/      seven stages, orchestrator, local worker
    api/           public/ (unauthenticated) and console/ (JWT)
    services/      review, card derivation, TipTap conversion
  migrations/      0001_initial.sql — the schema source of truth, and the whole of it
  tests/           test_invariants.py — the invariant suite
frontend/
  src/
    lib/api/       framework-agnostic data layer (keeps the Next.js port cheap)
    styles/        design-system.css (vendored Modernist) + youth.css (the theme)
    features/shell/    site bar, category drawer, mobile tabs, toast
    features/feed/     public masonry feed and the article page
    features/reader/   reader accounts, saved folders
    features/console/  review desk: queue, editor, sources panel
    routes/        mirrors a Next.js app/ tree one-for-one
  public/media/    the wordmark and the hero video
```

Two route groups that share only `App.tsx`:

| Group | Paths | Chrome |
|---|---|---|
| Public | `/`, `/a/:slug`, `/about`, `/join`, `/you`, `/contact` | site bar, category drawer, mobile tabs |
| Review | `/review`, `/review/login`, `/review/article/:id` | its own bar; nothing public links to it |

The review desk moved off `/console` and renders none of the public chrome. That
is discoverability, **not** access control — a URL is not a secret. What keeps
readers out is `RequireAuth` plus the router-level bearer check on every
`/api/console/*` route, which a reader token cannot satisfy (see below).

## Quickstart

Everything in containers except the model server:

```bash
# Every model call runs locally by default (LLM_PROVIDER=ollama,
# EMBEDDING_PROVIDER=ollama). Ollama stays on the host — a container on macOS
# has no Metal access, so a containerised llama3.1:8b would be CPU-only.
ollama pull llama3.1:8b          # both generative calls
ollama pull mxbai-embed-large    # embeddings, 1024-d to match EMBEDDING_DIM

docker compose up                # db -> migrate -> api :8000 + worker + web :5173

# Once, for a reviewer login. Its own service because seed_admin prompts for a
# password — an argument would land in shell history and in `ps`.
docker compose run --rm seed --email you@example.com --name "Your Name"
```

No `backend/.env` is needed: every setting in `app/config.py` has a working
local default. Create one (`cp backend/.env.example backend/.env`) when you want
hosted providers or an image key — compose picks it up if present and ignores it
if not. Source is mounted read-only over the image, so an edit needs
`docker compose restart backend`, and only a `pyproject.toml` change needs
`--build`.

## Two kinds of account

`users` are reviewers; `readers` are the public. They are **separate tables**,
and that separation is load-bearing rather than tidy. `articles.reviewed_by` is
a foreign key into `users`, so a row there is a claim about who is answerable
for a published article — one table with a role column would put a correctly-set
enum between a self-service signup and the review queue.

Their tokens are signed with the same key and separated by a `typ` claim
(`reviewer` / `reader`) checked in `decode_token_subject` **before** the account
lookup, so a reader token presented to `/api/console` is rejected as malformed
rather than merely failing to resolve — the separation survives a future change
to either query. `lib/api/client.ts` picks which token to send from the request
path, never from the caller.

A reader account does three things and no more:

- **Orders the feed.** Interests add a leading sort tier — the subjects you
  picked first, everything else below. Never a filter: an account must not
  quietly shrink the world, and filtering would make every *unclassified*
  article invisible to anyone with an interest set.
- **Keeps folders.** A shelf that survives the browser, which is the whole
  reason it is an account rather than `localStorage`.
- **Records a newsletter opt-in.** A boolean. Nothing sends anything yet, and
  the UI says so in those words.

## Model providers

Both the generative calls and the embeddings sit behind Protocols
(`llm/base.py`, `llm/embeddings/base.py`), and the concrete client is chosen in
one place per call type — `llm/factory.py` and `llm/embeddings/factory.py`. So
the local/hosted switch is config, not a refactor:

| | local (default) | hosted |
|---|---|---|
| `LLM_PROVIDER` | `ollama` — free, offline, no key | `anthropic` — `ANTHROPIC_API_KEY` + `EXTRACTION_MODEL`/`SYNTHESIS_MODEL` |
| `EMBEDDING_PROVIDER` | `ollama` — `mxbai-embed-large`, 1024-d | `voyage` / `openai` |

Two caveats when you make the switch:

- **Local quality is not hosted quality.** An 8B model extracts thinner claim
  lists and fails citation validation more often. The invariants still hold —
  a draft that fails validation is written as `validation_failed` and never
  reaches the review queue — you will just see more of them. Point
  `OLLAMA_SYNTHESIS_MODEL` at a larger local model if that gets noisy.
- **Changing the embedding provider needs a re-embed**, because vectors from
  different models are not comparable and the failure is silent. `sources.
  embedding_model` records which model produced each vector (local ones are
  namespaced `ollama/…`), so the cache re-embeds on mismatch — but the backfill
  is yours to run. `mxbai-embed-large` and `voyage-4` are both 1024-d, so that
  particular move is a re-embed and not also a migration.

The first real run behaved as designed rather than as hoped: the
`validation_failed` article was caught by invariant #2 for a grouped citation
marker (`[S1, S5, S8]`) the parser did not yet accept — the draft was kept out
of the review queue instead of shipping a broken citation. Grouped markers are
supported now.

Four measured findings, all since fixed. Each was found by looking at
real rows rather than by reasoning about the code, and two of them ran the
opposite way from what the design assumed.

- **Fixed — trial protocols were scoring `rct`.** Three of the 92. A protocol
  describes the randomised trial it *intends* to run, so the abstract
  heuristics read it as one, and `rct` has ceiling `supported`. Protocols are
  now refused at retrieval (DESIGN.md §4), and informative-but-unmapped
  publication types no longer fall through to prose.
- **Fixed — 41% classified `unknown`** (38/92). Sixteen were narrative reviews
  with no tier to go to, one a bare `Clinical Trial` missing from the map.
  After adding `narrative_review` and closing the mapping gaps, `unknown` is
  24/92 (26%) and every remaining one is a paper PubMed tagged only as
  `Journal Article`. Re-derive cached grades with
  `python -m scripts.reclassify_sources` after any classifier change.
- **Fixed — a retracted paper could be cited at full evidence grade.** The
  classifier consults the positive publication-type map *before* the negative
  set, so `Randomized Controlled Trial; Retracted Publication` graded as `rct`
  — ceiling `supported` — and a retracted trial nearly always carries its own
  design tag. The cap that was supposed to catch this applied only to papers it
  did not matter for. Retractions are now checked first, refused at retrieval,
  and re-checked on a schedule against PubMed and Crossref
  (`python -m scripts.check_retractions`). Measured on the live corpus: 90/90
  PMIDs and 92/92 DOIs resolved, **zero retracted**, verified against a known
  retracted control (DESIGN.md §4).
- **Fixed — a `supported` verdict could rest on a single cited study.**
  `check_verdict_within_grade` asked only how good the best source was, never
  how many there were. `supported` now requires two sources at a
  supported-tier grade, counted **per claim**, with the article taking its
  weakest claim's ceiling (DESIGN.md §4). Both existing articles pass — this
  closed a reachable gap rather than a realised one.

**Corrected 2026-08-21 — Voyage has been exercised.** This section previously
said no Voyage call had been made. All 92 rows carry
`sources.embedding_model = 'voyage-4'` with populated 1024-d vectors, created
during those two runs, and that string is written from
`VoyageEmbeddingProvider.model_id` and nowhere else — the Ollama provider
namespaces its own as `ollama/…`. The claim was inherited from the design docs
rather than checked against the database.

**Which generative provider those runs used is not recorded anywhere**, so the
table above no longer names one. Both `llm_provider` and `embedding_provider`
defaulted to `ollama` by then, but the embedding default was plainly overridden,
which means the defaults say nothing about the environment that ran them. From
now on `pipeline_stage_runs.model` records it per call; the two historical runs
are backfilled with their token counts and a NULL model, and therefore report an
unknown cost rather than a guessed one.

**Still not verified — needs an API key.** No call has been made to **Claude**;
that client and its token accounting are written against documented response
shapes only. Europe PMC and Semantic Scholar are wired but have not been enabled
in a run (`ENABLED_PROVIDERS=pubmed`). The re-rank bonus constants in
`retrieval/rerank.py` remain tunable starting values — no golden set exists yet
to measure them against.

## Tests

```bash
cd backend && pytest tests/ -q
```

Three groups:

- **`test_invariants.py`** — grounding and evidence-grading. Includes the tests
  that watch validation *reject* a draft: a hallucinated `S9`, an unresolvable
  source, a `supported` verdict on in-vitro evidence. An invariant nobody has
  watched fail is an invariant nobody knows is enforced.
- **`test_content.py`** — field bounds, TipTap conversion, card derivation
  (including that the tile's picture is the article's own first image, and that
  a YouTube block is deliberately not one — deriving a thumbnail would put a
  third-party request on every feed render).
- **`test_reader_accounts.py`** — the reader schema's SQL guarantees, which a
  fake session cannot express: the composite foreign key that makes "you can
  only save into your own folder" a database fact, the `(reader_id,
  article_id)` primary key that makes re-saving a *move* rather than a copy,
  and the CHECK that a handled contact request names who handled it. Needs a
  live database and skips silently without one.
- **`test_publish_path.py`** — a structural guard that greps the AST for any
  assignment of `published` outside `ReviewService.approve()`. It fails when
  someone *adds* a second publish path, which is the regression behavioural
  tests cannot anticipate.

## The four invariants

Each is enforced by a specific mechanism, not by convention. If you are
reviewing this design, these are the things to check:

1. **Nothing publishes without a human.** No code path from the pipeline reaches
   `published`; `ReviewService.approve()` is the only one, and a DB `CHECK`
   constraint refuses a published row without a reviewer.
2. **Every citation is real and was in the prompt.** `evidence/validation.py`
   checks each emitted handle against the exact set rendered into that prompt,
   then that each resolves to a real PMID/DOI. Failures never enter the queue.
3. **Evidence grade caps verdict confidence.** `evidence/grading.py`. A
   `supported` verdict on in-vitro sources is a validation failure, not a style
   note.
4. **The AI draft is immutable.** `original_content` is trigger-protected; human
   edits go to `edited_content`, giving a clean audit trail of what the model
   wrote versus what went live.

Plus one structural: the feed card is **derived** from the article, never
generated separately — headline, excerpt *and* the tile's picture, which is the
article's own first image. So a tile cannot promise something the article walks
back, in words or in pictures.

## Not medical advice

Every article carries an informational-not-medical-advice disclaimer, rendered
from a server constant rather than model output. Content is framed around
ingredients and the evidence for them — never around attacking brands.
